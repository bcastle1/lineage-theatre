# New versions from saved plans

The film library can create a separate browser draft from a privately saved plan. It rereads the authenticated plan detail and verifies the exact manifest SHA-256 and version identity before copying. The new draft receives a fresh film ID. Its duration starts at the saved target and remains editable. Creation neither regenerates the story nor requests payment or production.

The server plan contains screenplay, cast, themes, assumptions, scene direction, and source reference metadata. It does not contain the original uploads, extracted source text, photographs, or family narrative. The new draft contains one explicitly labeled derived text source: the complete saved screenplay plus the original plan ID/hash and original source IDs, names, types, and evidence hashes. Original reference IDs remain in that source; the editable cast and scenes reference the derived source where they previously referenced source material. An empty original reference list stays empty. Cast basis and dramatization text are preserved as claims to review, not newly verified historical evidence.

No uploaded file is manufactured or copied to IndexedDB. The draft's family narrative starts blank. Payment, prepared production, render jobs, shot state, media, archive state, generation attribution, source-reading claims, and prior consent are not transferred. The original saved plan, order, and any existing browser draft remain unchanged. A changed duration requires review and fresh preparation and pricing through the normal flow; this action does not enable unavailable production.

The complete derived source must fit the existing one-million-character story input limit and the film metadata must fit its existing 100,000-character limit. Oversized or unsupported saved records fail with an explicit error, never truncation. The implementation copies the saved screenplay once into its provenance source; it does not repeat the manifest's per-shot screenplay or claim recovery of missing original documents.

The workspace writes the complete account-scoped browser project list and verifies exact readback before changing the active draft. In-flight work is rejected after unmount or account changes, and repeated clicks share the existing operation lock. A storage failure leaves the current UI on the original film; an unconfirmed write may require a library reload to discover whether the browser accepted it. No server or financial mutation is part of this operation.
