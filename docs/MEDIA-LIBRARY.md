# Original media library

Film library and the main navigation open `#media`. Film creation uploads also save originals to this library. Administration includes Media library at `#admin/media`, covering every account. Existing finished-film archives remain separate.

Originals use private Vercel Blob storage. `/api/media` requires the current approved session for listing, upload reservation, verification, file reads, and changes. Other customers cannot read files or metadata. Administrators can access all source media. Private bytes are streamed by the authenticated route with range support, attachment names, no-store and nosniff headers. Documents are attachments except PDFs. File-format declarations are not malware scanning.

Each original has independent customer state (active, archived, trash) and administrator archive state. Customer archive/trash changes never delete bytes. Administrators may permanently delete only from their archive, with a current revision and the exact confirmation DELETE. Deletion blocks callbacks and reads before removing bytes. Storage failures leave a retryable deletion record. An active upload token delays permanent deletion until its 10-minute lifetime plus a one-minute grace period expires. A minimal tombstone prevents the same source identifier being resurrected; it contains no original filename or content. The administrative purge event records the actor, owner reference and media ID. Copies previously downloaded to a device and already-rendered films are not erased.

Uploads are limited to 100 MB per file, 2,000 retained files and 10 GB per customer. Reservations and organization use conditional record writes. Customer trash still counts toward retained storage. Approved types match the source importer: JPEG, PNG, WebP, PDF, DOC, DOCX, TXT, Markdown, GEDCOM, CSV, MP3, WAV, M4A, OGG, MP4, MOV and WebM. Uploads use private Blob client tokens, immutable per-account paths and the SDK's signed completion callback. File size, path, current owner approval and content type are verified before readiness.

Copy browser sources uploads files in IndexedDB belonging to the signed-in account's known project IDs, including detached sources whose originals still exist there. It reports missing files and partial failures. It requires the user's action after a visible retention notice, never silently exports old browser-only files. Work on another browser/device must be copied from that device; originals already erased cannot be reconstructed. Project drafts and extracted text still stay in local browser storage. Reusing media downloads and extracts the original into the selected local film without duplicating the server original.

Listing pages contain at most 50 metadata records. Load more advances even through pages without matching states; search and type filters clearly apply only to loaded items. No existing source or account data migration runs during deployment.

Validation: `node --test tests/media-library.test.mjs`, the full `pnpm test` suite, `pnpm run build`, and authenticated upload/download, state retention, archive, deletion, reload and responsive checks on the deployed domain. Only synthetic QA files may be removed during release verification.
