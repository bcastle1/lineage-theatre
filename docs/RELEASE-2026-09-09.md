# September 9, 2026 studio release

## Verification before promotion

- Authentication tested against the actual private account store with an isolated synthetic identity: invalid login, origin mismatch, forced first-login gate, short-password rejection, successful password rotation, rejection of the old password/session, and access with the replacement session.
- Automated tests cover salted password verification, exact-origin validation, body limits, cookie restrictions, signed-session tampering and expiry. Real user passwords were not changed during QA.
- Browser tests imported fictional TXT, DOCX, PDF and JPG sources. Text extraction and thumbnail display succeeded. Project/source/output data survived a reload.
- Actual MP4 created in Edge: 1920 x 1080, 15.009 seconds for a 15-second selection. Player reached its end, with no media error. A native download link targets the same playable film Blob with the `.mp4` filename. The browser automation download event was unavailable; file-save completion must be checked by the end user in their browser.
- Deployed API returned ten Gemini suggestions, ten refreshed suggestions with zero repeated titles, and a five-scene / 53-word plan for a 30-second request. Primary-model capacity errors led to a bounded fallback to another Gemini model; video submissions never retry automatically.
- Provider account checks: Runway authenticated but zero API credits; ImagineArt has no connected API credential. These are shown explicitly. Archive film creation works without those credits. Paid shot completion cannot be verified until an account is funded.
- Desktop and 390 x 844 mobile checks found no horizontal overflow and no text nodes above font weight 400. Library navigation, step selection, theme selection/refresh, duration, consent validation, and render completion produce visible feedback.
- Browser console contained extension message-channel errors; the observed application flow had no JavaScript exception or media error.

## Visual fidelity ledger

The generated concept established a warm light canvas, forest accent, narrow persistent navigation, four-step film workflow, a restrained form panel, and an archival photograph beside the primary form.

1. Layout: implementation retains the sidebar, top project selector, four-step progression, form panel, and photographic column. Runtime and narrative controls appear in their appropriate workflow steps.
2. Typography: Georgia headings and regular sans-serif controls preserve editorial character while all weights are explicitly 400. Decorative search, unimplemented avatar menu, and bold emphasis were omitted to satisfy the user's compact and functional requirements.
3. Palette: warm light background, white fields, forest primary actions, muted green-gray borders, and semantic success/error treatments match the concept's direction.
4. Imagery: a separate high-resolution generated archival portrait/letters/reel asset replaces the illustrative concept photo, with the same natural materials, framing, and visual purpose. It is labeled illustrative, never represented as a user's ancestor.
5. Density: name/title share a row on large screens. Uploaded sources have real thumbnails, extracted text, and editable source notes. A single historical period/place field keeps the requested timeline control compact.
6. Responsive behavior: navigation becomes a compact top bar; fields stack, the decorative photo hides, and all four steps remain reachable without horizontal scrolling.
7. Interaction: all controls remain native HTML/React. Inputs, source extraction, scenes, render progress, and playback reflect actual data and actions.

## Delivery constraints

Projects and files remain in the current browser; this release does not provide cross-device cloud sync. Original project records remain available for explicit import. External studios require their own accounts and uploads. Spoken narration uses an uploaded recording; without it, the film uses captions and optional ambient score. Generated five-second shots loop within longer scenes and carry an AI dramatization label.

Final commit, deployment, custom-domain checks and email receipts are reported in the delivery response.
