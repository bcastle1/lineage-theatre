## Acceptance gates

1. **Review and deploy only the approved commit.** Run the full repository test suite and production build, inspect the final diff, and retain provider/payment default blocks. After authorized deployment, verify Vercel READY, exact served commit/assets and successful signed-in owner and customer behavior. A loaded sign-in page or saved environment variable is insufficient.
2. **Verify account operations in the deployed environment.** Preserve existing users and roles; test registration, normal and expired-password renewal, logout replay, idle/absolute expiry, MFA enrollment/challenge/recovery and concurrency with designated test accounts. Check mail permissions, requested-message acceptance, received link, account binding, expiry and replay without exposing tokens. Do not claim legacy users are universally verified, enrolled or compliant.
3. **Verify private preparation and worker delivery.** Confirm explicit storage consent, screenplay/manifest download, isolation from another customer, administrator authorization, and browser draft/source preservation. Select and configure durable worker execution, retries/reconciliation, private artifact storage, output retention and playable-media acceptance before real rendering.
4. **Obtain the complete MagicLight contract.** The [pending vendor inquiry](MAGICLIGHT-API-REQUEST.md) covers official authentication, entitlement, uploads/reference assets, clip submission/status/output, request lookup/idempotency, cancellation, character/audio continuity, actual highest quality, bounded costs, failure charges, retention and API resale rights. Implement the adapter only from verified contracts. Do not assume a sandbox exists or that purchased API credits establish these capabilities.
5. **Complete Intuit sandbox lifecycle and card-entry review.** Use the existing intended grant to verify company identity and granted capabilities, denial, refresh/rotation, revocation and reconnect. Then verify a supported hosted-fields/tokenization flow and its actual PCI responsibilities before accepting card input. Successful CORS preflight or fabricated token creation is not a hosted-fields or PCI attestation. Separately test exact quote/capture, decline, uncertainty, concurrency, duplicate prevention, refunds, receipt and reconciliation. No real card data belongs in app requests, logs or test fixtures.
6. **Resolve production merchant and legal requirements.** Complete the current assessment using actual company facts and reviewed operational evidence. Confirm scope consent, merchant capability, approved production credentials, commercial/refund terms and applicable security/PCI obligations. Legal history, sanctions disclosures and certifications require authorized company attestations; code cannot answer them. Obtain approval for a bounded real charge/render and verify their outcomes before enabling customer production. Keep settlement, processor fees, provider usage expense and approved accounting mappings distinct.
